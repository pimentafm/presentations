O problema

Por que dado geo é diferente?

Para o pipeline, geometria parece só mais uma coluna. Não é: ela carrega um sistema de referência, relaciona-se por topologia e chega em formatos pensados para desktop, não para lakes.

01 · CRS
Mesmo número, outro lugar
Sem SRID explícito, (-47, -15) pode ser Brasília ou o meio do Atlântico. Área em graus² não significa nada.
02 · JOIN
Sem chave de junção
Imóvel × alerta × bioma se relacionam por ST_Intersects, ST_Contains, ST_DWithin — não por equi-join.
03 · FORMATOS
Legado de desktop GIS
Shapefile, KML, File GDB: orientados a linha, sem schema forte, sem predicate pushdown.
04 · VOLUME
Raster exige outro modelo
TBs de imagens multibanda onde tempo é dimensão. Não cabe em tabela — cabe em array.
CRS · topologia · formato · volume IDE = PLATAFORMA QUE PADRONIZA ISSO

Tipos de dado espacial.

SHEET 05 / {{TOTAL}}
O tipo que mente

CRS é parte do schema.

Uma geometria sem CRS é como um timestamp sem timezone: parece certo até alguém agregar.

  • Geográfico vs projetado — EPSG:4674/4326 em graus; UTM ou Albers em metros. Para medir: geography ou a projeção certa (próximo slide).
  • Ordem dos eixos — GeoJSON é lon, lat; o EPSG:4326 oficial é lat, lon. Trocar é o bug nº 1.
  • Validade — auto-interseção e anéis abertos quebram ST_Intersection e ST_Union. ST_MakeValid na entrada.
  • Datum legado — SAD69 e Córrego Alegre ainda chegam de INCRA, cartórios e prefeituras. A diferença para o SIRGAS 2000 é de dezenas de metros: converta com a grade NTv2 do IBGE, nunca só trocando o SRID.
  • Serialização — WKB no storage, WKT para debug, GeoJSON na API. Nunca string livre.
-- Mesmo polígono, três "áreas" SELECT ST_Area(geom) -- graus²: sem significado físico , ST_Area(geom::geography) -- m² no elipsoide (geodésico) , ST_Area(ST_Transform(geom, 5880)) -- m² na Policônica: não é equivalente, erra longe do MC FROM talhoes;

Toda projeção distorce algo

Projeção é escolha, não detalhe.

Nenhuma projeção preserva área, forma e distância ao mesmo tempo. A pergunta do pipeline decide a projeção, e não o contrário.

Pergunta do pipeline Projeção · propriedade
Área (ha de imóvel, desmatamento) → Equivalente · Albers SIRGAS 2000 ou geography
Distância e buffer locais → UTM do fuso certo · EPSG:31978–31985 (18S–25S)
Medida nacional, vários fusos → Elipsoide · geography, sem projetar
Mapa temático do Brasil → Policônica · EPSG:5880 (convenção IBGE)
Tiles e mapa web → Conforme · Web Mercator 3857, só para desenhar
-- Quanto o Web Mercator infla a área? (fator ≈ sec²φ) SELECT nm_mun, ST_Area(ST_Transform(geom, 3857)) / ST_Area(geom::geography) - 1 AS erro FROM municipios WHERE nm_mun IN ('Sinop', 'Porto Alegre'); -- ≈ +4,4 % · ≈ +33 %
Equivalente · conforme · equidistante epsg.io · SIRGAS 2000

De onde vem o dado

Ingestão geo

GDAL/OGR é o "conector universal": lê 200+ formatos e está por baixo de quase tudo — GeoPandas, DuckDB, QGIS, rasterio.

  • Downloads em lote — SHP/GDB de órgãos públicos (SICAR, IBGE, INCRA). Batch idempotente, particionado por UF e data.
  • APIs OGC — WFS e OGC API Features paginadas. Trate como qualquer API REST: retry, cursor, rate limit.
  • Catálogos STAC — imagens de satélite por bbox, data e cobertura de nuvem. Ingestão é só de metadados; pixels ficam no bucket de origem.
# Bronze → Silver: shapefile do SICAR para GeoParquet conformado ogr2ogr -f Parquet silver/car/uf=MT/area_imovel.parquet bronze/car/uf=MT/AREA_IMOVEL.shp \ -t_srs EPSG:4674 -makevalid -nlt PROMOTE_TO_MULTI \ -lco COMPRESSION=ZSTD -lco WRITE_COVERING_BBOX=YES

O JOIN mais caro do seu pipeline

Spatial join & H3

Sem chave, o join ingênuo é um produto cartesiano. O truque: transformar geometria em chave discreta para filtrar candidatos, e só então aplicar o predicado exato.

  • Filtro + refino — bbox / célula descarta 99% dos pares; ST_Intersects roda só nos candidatos.
  • H3 como chave — hexágonos hierárquicos viram BIGINT: equi-join, partição e agregação em qualquer engine.
  • Layout do arquivo — ordenar por H3 ou curva de Hilbert antes de escrever faz o bbox das estatísticas pular row groups.
-- Sedona (Spark SQL): imóveis CAR × alertas DETER WITH c AS (SELECT car_id, geom, explode(ST_H3CellIDs(geom, 7, true)) AS h3 FROM silver.car), a AS (SELECT alerta_id, geom, explode(ST_H3CellIDs(geom, 7, true)) AS h3 FROM silver.deter) SELECT DISTINCT c.car_id, a.alerta_id FROM c JOIN a ON c.h3 = a.h3 -- equi-join barato (BIGINT) WHERE ST_Intersects(c.geom, a.geom); -- predicado exato só nos candidatos
Filter → refine h3geo.org

De pixel a coluna

Raster pipelines

Raster raramente é o produto final. O padrão é: buscar no STAC, ler só a janela necessária dos COGs e reduzir para uma tabela por polígono.

STAC search→ COG (range read)→ datacube lazy→ índice (NDVI)→ estatística zonal→ tabela Gold
from pystac_client import Client import odc.stac from exactextract import exact_extract items = Client.open("https://earth-search.aws.element84.com/v1").search( collections=["sentinel-2-l2a"], bbox=talhoes.to_crs(4326).total_bounds, datetime="2026-09", query={"eo:cloud_cover": {"lt": 20}}, ).item_collection() ds = odc.stac.load(items, bands=["red", "nir"], resolution=10, groupby="solar_day") ndvi = ((ds.nir - ds.red) / (ds.nir + ds.red)).median("time") gold = exact_extract(ndvi, talhoes.to_crs(ds.odc.crs), ["mean", "stdev"], output="pandas")

Um dado, várias escalas

Escala & generalização

A escala de origem define a precisão do dado. A escala de exibição define quanto detalhe vale a pena trafegar. Generalizar é um job da Gold, não um efeito colateral do tile server.

  • Precisão ≠ casas decimais — um limite em 1:250.000 tem incerteza de dezenas de metros. Guardar 15 casas é ruído que pesa no storage e no tile; ST_ReducePrecision na Gold.
  • Simplificar sem abrir buracos — ST_SimplifyPreserveTopology trata cada feição isolada, e municípios vizinhos se descolam. Em malhas, use ST_CoverageSimplify (PostGIS 3.4+).
  • Seleção por zoom — o tippecanoe decide o que cai em cada nível (--drop-densest-as-needed): o imóvel pequeno some em z6 e volta em z12.
-- Gold: uma geometria por faixa de escala, fronteiras compartilhadas intactas SELECT cd_mun , ST_CoverageSimplify(geom, 0.01) OVER () AS geom_z4 -- ~1 km: país inteiro , ST_CoverageSimplify(geom, 0.001) OVER () AS geom_z8 -- ~100 m: estado , geom AS geom_full -- detalhe total FROM silver.municipios;

Simbologia como código

O mesmo dado, com outra classificação, conta outra história. Quebras, paleta e normalização são decisões de produto: versione junto com o pipeline.

Mapa temático

Classificar & normalizar

  • Normalize · contagem absoluta por município vira mapa de população; use taxa (% da área) ou densidade
  • Classificação · quantis, Jenks ou intervalos iguais mudam a leitura; fixe método e quebras
  • MAUP · o padrão muda com a unidade (município, H3 res 7, res 9); mantenha várias resoluções na Gold
  • Paleta · sequencial para magnitude, divergente para desvio; teste para daltonismo

08 · MAPA
Contagem absoluta
Total por município só destaca município grande. Normalize por área ou população.
09 · TOPOLOGIA
Simplificar feição a feição
Vizinhos se descolam e surgem gaps no mapa. Em malhas, use coverage simplify.
